## Introduction to tcpdump

---

### Overview

In this lab, I practiced using `tcpdump`, a command-line network analysis tool used to capture, filter, display, and inspect network packets.

I explored basic packet capture, verbose output, DNS traffic filtering, and saving captured packets to a `.pcap` file. I also learned how to read a previously saved packet capture for further analysis.

These skills are useful for understanding network communications, troubleshooting connectivity problems, and investigating suspicious network activity.

## 1. Identifying the Network Interface

Before capturing traffic, I checked the available network interfaces.

```bash
ip link
```

The lab used `eth0` as the example network interface.

---

## 2. Capturing Network Traffic

To begin capturing packets on `eth0`, run:

```bash
sudo tcpdump -i eth0
```

The command displays packets as they are captured and continues running until stopped.

![1](https://i.imgur.com/GL6v6uG.png)

After stopping, `tcpdump` displays a summary of the capture, including packet counts.

### Command Breakdown

| Option    | Purpose                                    |
| --------- | ------------------------------------------ |
| `sudo`    | Runs the command with elevated privileges  |
| `tcpdump` | Starts the packet-capture utility          |
| `-i eth0` | Specifies the network interface to monitor |

---

## 3. Using Verbose Output and Disabling Name Resolution

To display more packet details and avoid reverse DNS lookups, run:

```bash
sudo tcpdump -i eth0 -vn
```

![2](https://i.imgur.com/8hPExEM.png)

### Command Breakdown

| Option    | Purpose                                   |
| --------- | ----------------------------------------- |
| `-v`      | Enables verbose output                    |
| `-n`      | Prevents address and port name resolution |
| `-i eth0` | Selects the interface                     |

Verbose output provides additional information about packet headers, including IP-related fields such as time-to-live and IP flags.

Disabling name resolution helps keep the output numeric and can reduce extra DNS traffic generated by lookups.

---

## 4. Filtering DNS Traffic

The lab captured DNS traffic involving the DNS server `8.8.8.8` on port `53`.

```bash
sudo tcpdump -i eth0 -vn host 8.8.8.8 and port 53
```

![3](https://i.imgur.com/3dbOuld.png)

This filter matches packets where the source or destination address is `8.8.8.8` and the source or destination port is `53`.

### Filter Breakdown

| Filter         | Purpose                                             |
| -------------- | --------------------------------------------------- |
| `host 8.8.8.8` | Matches traffic to or from the specified IP address |
| `port 53`      | Matches traffic using port 53                       |
| `and`          | Requires both filter conditions to match            |

### Running the Capture in the Background

The lab placed the capture in the background so DNS traffic could be generated separately.

```bash
sudo tcpdump -i eth0 -vn host 8.8.8.8 and port 53 &
```

List running jobs:

```bash
jobs
```

![4](https://i.imgur.com/8Awuvtu.png)

Note the job number shown by the terminal. Then generate a DNS query:

```bash
dig @8.8.8.8 example.com A
```

![5](https://i.imgur.com/svMF9Au.png)

Bring the capture job back to the foreground, replacing `1` with the job number displayed by `jobs`:

```bash
fg %1
```

![6](https://i.imgur.com/41rbn6Y.png)

### Understanding the DNS Packets

The lab demonstrated two main packet types:

1. **DNS query:** The client asks the DNS server for the IPv4 address associated with `example.com`.
2. **DNS response:** The DNS server returns a response containing the result of the query.

DNS commonly uses UDP port 53, although it can also use TCP.

## 5. Capturing HTTP Traffic to a PCAP File

Next, I captured traffic using port 80 and saved the packets to `http.pcap`.

```bash
sudo tcpdump -i eth0 port 80 -w http.pcap &
```

![7](https://i.imgur.com/2OOD231.png)

### Command Breakdown

| Option         | Purpose                            |
| -------------- | ---------------------------------- |
| `-i eth0`      | Selects the network interface      |
| `port 80`      | Filters traffic using port 80      |
| `-w http.pcap` | Writes captured packets to a file  |
| `&`            | Runs the command in the background |

Check the background jobs:

```bash
jobs
```

![8](https://i.imgur.com/YWPG5sQ.png)

Generate HTTP traffic using `curl`:

```bash
curl http://example.com
```

![9](https://i.imgur.com/Ws2bX5w.png)

The command requests the page and displays the returned HTML in the terminal.

Bring the capture back to the foreground, replacing `1` with the appropriate job number:

```bash
fg %1
```

![10](https://i.imgur.com/TeX4uRh.png)


> **Security note:** The lab uses HTTP on port 80 to demonstrate packet capture. HTTP traffic is generally unencrypted, so captured application data may be readable. HTTPS normally protects application content through TLS.

---

## 6. Reading a Saved Packet Capture

After creating `http.pcap`, I used `tcpdump` to inspect the saved packets.

```bash
tcpdump -r http.pcap
```


### Command Breakdown

| Option      | Purpose                                     |
| ----------- | ------------------------------------------- |
| `-r`        | Reads packets from an existing capture file |
| `http.pcap` | The saved packet-capture file               |

Reading a file does not require the same elevated privileges as capturing live traffic in this lab.

A PCAP file stores captured packet data in a format that network-analysis tools can inspect. It is a binary file, so printing it directly with `cat` will not provide a useful human-readable packet summary.

## Key Concepts Learned

* **Packet capture:** Recording network packets for analysis.
* **Network interface:** The interface through which traffic is observed.
* **Packet filtering:** Selecting packets based on addresses, ports, or other criteria.
* **DNS:** A service that resolves domain names to IP addresses.
* **HTTP:** A protocol used to transfer web content.
* **Verbose output:** Additional information about packet headers.
* **PCAP:** A file format used to store captured packet data.
* **Live capture vs. file analysis:** Capturing current traffic and examining previously saved traffic are different workflows.

## Cybersecurity Relevance

`tcpdump` is useful in both IT support and Security Operations Center (SOC) work.

* **Network troubleshooting:** Investigate connectivity and communication issues.
* **DNS analysis:** Inspect DNS queries and responses.
* **Traffic filtering:** Narrow an investigation to a specific host or port.
* **Incident response:** Review captured traffic to investigate suspicious communications.
* **Protocol analysis:** Examine packet headers and understand network behavior.
* **Evidence collection:** Save packet captures for later investigation, subject to appropriate authorization and handling procedures.

## Troubleshooting Notes

| Problem                          | What to check                                                                     |
| -------------------------------- | --------------------------------------------------------------------------------- |
| Permission denied                | Use `sudo` for live packet capture when required                                  |
| No packets appear                | Confirm the interface name and generate traffic that matches the filter           |
| Wrong interface                  | Run `ip link` to inspect available interfaces                                     |
| Filter captures no traffic       | Verify the IP address, port, and filter conditions                                |
| Capture file is missing or empty | Confirm the capture was running while traffic was generated and stopped correctly |
| Output is difficult to read      | Try `-n` to disable name resolution or `-v` for more detail                       |
| Cannot return to the capture     | Run `jobs` and use `fg %1` with the correct job number                            |
